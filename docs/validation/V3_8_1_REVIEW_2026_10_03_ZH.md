## 设计取舍与边界

- **不恢复索引开关**：较新的 `v3.8.1_describe_table结构化索引_概要设计与实施计划_v2.0.md` 第 7 行明确记录维护者确认“不加开关、get_full_schema 不变”。云端评审依据旧稿提出的默认关闭要求不成立。保留 `describe_table()` 默认采集；它新增默认元数据工作和信息披露，但没有开放原始 SHOW 或扩大允许的表集合。
- **索引不是完整 DDL**：兼容保留 `columns`；`key_parts` 描述方向和后端属性，SQLite 提供 collation，MySQL 提供前缀长度与索引可见性。未知属性用 null，不把“未采集”写成“不存在”。表达式文本、部分索引谓词、外键、check、注释和基数仍不提供。`complete` 只表示这次清单完整。
- **独立的索引采集预算**：最多 128 个索引、2048 个键项、64 KiB UTF-8 JSON；超过任一项整组返回 `indexes=null/indexes_status="unavailable"`，列仍可用，不返回部分清单。它不是查询结果的 `limits.result_chars`，也不是整个 `describe_table` 的硬期限。索引查询共享协作式剩余时间；连接建立、锁等待和驱动限制仍适用。`get_full_schema()` 不采集索引。
- **SQLite main 限定范围**：本轮固定元数据路径，不宣称静态 SQL 检查能够隔离受信任 Python Skill 任意创建的会话临时对象。Python Skill 仍不是沙箱；普通查询中的未限定对象解析仍属于该信任边界。
- **PRAGMA 名称边界**：精确内置 PRAGMA 对象名保守保留，不靠列名前缀判断；同名业务对象也可能被拒绝。规则来自已核对的 SQLite 内置集合，不保证涵盖任意扩展将来新增的对象。
- **结果解释仍是行为约束**：`execution_outcome` 与 `success` 分开；本次拒绝不能证明旧请求未提交，也不能证明预览值仍是现状。可明确回答“当前状态未核验”，不强制每次解释都查库。正常获批的首次执行仍允许，错误/未知结果/拒绝后不得自发重试或换入口。MRTR 仍是可信 Host 模式，不认证真人，也不关闭 preview/execute。
- **令牌验证的准确边界**：确认的令牌拒绝发生在框架执行边界前；托管 confirm 复用计划。命令式 Skill 的构造、适配器获取或就绪检查可以早于令牌验证，不能宣称“任何 Skill 代码之前验证令牌”。受信任扩展不得在这些阶段偷偷写入。

限制性白名单使用 MySQL 兼容的 CTE 定义顺序；SQLite 特有前向引用和省略 `RECURSIVE` 的递归写法可能被拒，应调整定义顺序并显式声明递归。
