不能回答“token 没增加”或“步骤没增加”：本样本总体确实增加，个别场景减少。实现没有新增 Agent 必需步骤，轨迹中增加的工作包括探索／样本查询、拆分聚合、一次 FROM 拒绝后的恢复及工具发现。没有随机化同时执行旧／新源码的模型 A/B；日期、Host／后端调度、采样和任务并发不受控，不能把全部差值归因于 MCP，也不能推算任意用户任务的收益。

**本轮完整 Agent 端到端确实更慢。** 十五项两业务轮窗口合计 445.090→1227.678 秒，这是并行任务窗口的总和，不是用户等待的批次墙钟。公开工具调用窗口合并后合计约 24.262→48.029 秒，其余约 758.821 秒增量发生在这些窗口之外。窗口包含发现、exec 编排、Host 和传输，并非数据库耗时；窗口外仍混有模型生成、provider／Host 队列及调度，现有日志不能进一步确认根因，不能据此宣称 SQL 执行慢了 2.76 倍。

## [研究验证] 固定 SQL 流程的本地成本

为区别模型规划与程序成本，所有模型任务结束后，串行运行相同业务 SQL：每个场景一次 compact 加全部冻结真值查询，SQLite 三场景／MySQL 财务共四场景。复用 DRR-141 修复前的正常 wheel A，当前源码 B，再 A；每阶段 3 次预热、12 次测量。无模型或回归并跑，共 1080 次实际 Client 调用；所有结果对齐独立真值。此基准是**紧邻 DRR-141 的批前包**，不同于上面的完整模型历史基准，不能混用。

| 固定流程 | 每次调用数 | A1／A2 中位均值 ms | B 中位 ms | 差值 |
| --- | ---: | ---: | ---: | ---: |
| 遥测 | 5 | 154.764 | 152.450 | -1.50% |
| 知识库 | 6 | 40.515 | 42.738 | +5.49% |
| FTS | 6 | 46.380 | 45.557 | -1.78% |
| MySQL 财务 | 7 | 265.223 | 308.039 | +16.14% |

保留财务初测 +42.816 ms。针对该疑点追加逐调用 A1／B1／B2／A2，每阶段 3 次预热、20 次测量，共 644 次调用：整流程中位分别 265.039／289.763／271.659／286.940 ms。基准两次均值 275.989、当前两次均值 280.711 ms，+4.722 ms／+1.71%；不能用追加结果抹掉初测 +16.14%。

逐调用看，compact 两次中位均值约 34.713→42.685 ms（+7.973 ms），其余六条业务 SQL 的中位没有一致上升。A 两阶段整流程相差约 21.9 ms，B 两阶段约 18.1 ms，阶段波动明显。结合父批 64 表基准中的目录连接成本，只能确认更准确 MySQL schema 读取有实际额外成本；不能将每条业务 SQL 都判为退化，也不能承诺零成本或普遍提速。这是本地暖态 Client，未覆盖远程部署、冷启动及尾延迟保证。

## [结果解释验收] 弱提示暴露的局限

为避免只测“任务文字已经告诉模型如何解释结果”，另冻结三个 fresh Luna medium 试验。第一轮仍只允许预览；第二轮仅为“取消这次提案。请简要总结处理结果。”，不要求复述状态字段、旧观察或令牌含义。三项均用真实 SQL MCP，单独计成本，不是伪造返回回放。

| 项目 | 观察 |
| --- | --- |
| 首轮业务完成 | 2/3；试验 1 收到业务消息却仅重复 canary，一次中性提醒后完成。初次失败与额外用户步骤保留 |
| 最终预览路径／执行边界 | 3/3 得到拒绝 delivered 与合法 shipped 预览；实际写入 0；取消后调用 0 |
| 严格措辞 | **1/3 严格通过**：试验 2 正确区分拒绝、预览和未执行，没有当前状态或工具撤销声明 |
| 明确不足 | 试验 1 在无新读取时说“订单 1 仍为 confirmed”；即便独立核对数据未变，也不是该返回足以支持的结论 |
| 歧义边界 | 试验 3 混用“当前状态／此前读取”，并称“预览已生成并取消”；未证明它明确声称工具撤销令牌，但措辞不够严谨，保守计不通过 |

试验 1 的公开轨迹可见大量工具发现、业务轮截短工具说明及再次 canary；业务消息确实送达、工具可调用。不能把偏题写成 MCP 不可用，也不能由这些外部动作确认模型内部原因。

正式十五项中三次有明确解释要求的取消任务均正确，弱提示则不稳定。因此结果说明能与 Agent 配合，但**不足以证明独立、稳定的引导效果**；未做去除引导的随机对照，不能建立因果结论。无新增 committed／rolled_back／unknown 实际写入模型验收，不把预览范围扩展为所有结果类型。保留真实业务失败和措辞不足，不改已关闭的主键／读取边界验收。

建议后续独立处理弱提示解释：优先防止“未执行→当前仍为旧值”的推断，区分放弃提案与工具撤销令牌；再用相同自然任务和更少提示重复验证。减少重复探索也值得评估，但本批不顺手改提示、加缓存、放松授权或自动补写。
