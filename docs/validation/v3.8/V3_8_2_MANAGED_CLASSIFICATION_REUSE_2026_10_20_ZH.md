# v3.8.2 readiness 拆分与受管纯分类复用

日期：2026-10-20。范围：维护者批准本轮① readiness 职责拆分、②实例内有界纯分类复用；③ SQLite hint 形注释、④ MySQL optimizer hint、⑤ HIGH_NOT_PRECEDENCE 兼容留待单独验收。版本仍为 v3.8.2，保留显式 sqlparse 回退与依赖，未改私有配置、grant 或配置库业务数据。

本轮已落地两项优化；源码、安装、成本和维护者重启后的驻留验收分层记录。源码／包检查以及维护者重启后的 **22/22 项限定原生验收均通过**。旧迁移的成本退化和已通过的 16 项原生核验保留原始源码归属。

| 变更 | 之前及原因 | 现在的方案 | 收益 | 代价／限制 |
| --- | --- | --- | --- | --- |
| readiness 职责 | 执行入口为取 schema 字段调用完整可用性，顺带重做计划分类 | 发现与执行入口共享依赖／schema 判断；发现另做完整策略 | 固定六调用由 11 次分类降到 7 次，减少无用重复 | 增加一项专用私有 helper，仍核验元数据，不缓存目录 |
| 纯分类复用 | 相同 SQL／方言会话／解析器被重复解析 | GatewayRuntime 实例内最多 128 项 LRU，缓存不可变 PolicyDecision | 同一任务冷轮实际分类 1 次、热轮 0 次；原两份计划的 SQL 相同，可共用分类 | 保留最多 128 项输入／结果引用，按项非字节；并发 miss 可重复计算 |
| 执行边界 | 目标语义、授权及 token 均需实时处理 | 命中只省分类；确认消费 token 后仍 resolve 实际目标 | 不拿旧上下文或旧授权批准新请求，原 SQL／绑定／COMMIT 证据保持 | 每次必要的上下文获取和独立校验成本仍在 |
| 生命周期与回退 | 实例关闭及显式回退必须明确归属 | 实例独享、关闭清空（registry 清理异常也清空），parser 入键 | 不跨实例或解析器混用；无额外 TOML 开关／依赖／Agent 步骤 | 临时 sqlparse 双路径测试继续保留，兼容细化另做 |

缓存键使用原 SQL 字符串、整个冻结 DialectContext 和选定 parser；包含方言、完整 sql_modes、CTE 大小写及默认 schema。名称内空白／点号与限定名不合并，不 trim／重写原 SQL。键不含 grant 或参数，因为值只回答语句分类，不能批准写入。确定性分类拒绝也可复用；连接获取在缓存外，抛出且未转换为决定的异常不缓存。解析错误如果已转为固定纯拒绝决定，可以按同一精确键复用。

实现只改四个运行模块：core/runtime、core/mutations、skills/access、skills/mutation。分类器 core/managed_sql 内容摘要未变；真实 MySQL 每物理会话初始化／退休约定保持，不增加每请求 SQL mode 查询。直接调用 run_managed_mutation 时不传分类回调仍用原纯分类器；服务运行实例显式传入其有界复用函数。

## 验证与成本

- A1 独立检查：197 项相关回归与 5 项职责／schema 边界通过。六调用为 list_skills、详情、更新预览／确认、恢复预览／确认，只写自动清理的 SQLite。
- 完整校验器的 980 组 SQL／上下文配对（1960 次 full-validator 调用）、6 个注释补例及 98 项 SQLite 非执行计划，与前轮持久化结果完全一致。未调整 hint 或 HIGH_NOT_PRECEDENCE 拒绝。
- 实例复用重放 1960 组 SQL／上下文／解析器组合，3920 次缓存 API 检查均与纯分类器相同；容量保持 128。部分语料 SQL 重复，组合数不等于唯一 cache key 数。
- 独立非计时六调用冷／热两轮：总计 14 次分类检查、14 次目标上下文获取、实际分类 1 次。计数与计时分开，未向生产工具添加追踪或模型步骤。
- 新回归覆盖名称／空白／parser／完整上下文键、逐出／关闭／实例隔离、并发一致、异常不缓存、暖态下权限／profile／alias／参数／缺表拒绝，以及两协议下消费后上下文变化／失败与 token 重放拒绝。受管原 SQL、绑定、回滚和缺少 COMMIT 证据沿既有测试保留。
- 最终全量 **2815 passed／4 skipped**；类型／提示及安装提示检查通过，77 项运行资源与独立 wheel 一致；源码／安装两协议各 **40 次真实 stdio** 通过。未新增完整模型试验、配置 MySQL 写入或 provider token A/B；旧 Luna 试验不重新归属。

A1 已完成一次独立 A/B/A：现代协议六调用中位数 56.824→54.108ms（下降 4.78%），legacy 93.402→89.052ms（下降 4.66%）。基线为本轮改前的 **77 资源、已完成 SQLGlot 迁移的版本**，不是 HEAD 或旧 76 资源版本。最终复用另完成 A/B/A：现代 81.731→68.713ms（-15.93%），legacy 130.156→125.809ms（-3.34%）。A1 legacy 前后基线漂移 -31.62%，最终 legacy 漂移 -5.93%；不能据此精确分摊两项优化的贡献，也不得把各批不同时间的绝对毫秒相减作为因果结论。

每次成本对照每协议 A/B/A 三阶段，各 8 轮预热及 40 轮计时；共 1440 次计时、288 次预热调用。周期为六次 client.call_tool 往返之和，不含进程启动、模型思考、本地编排／断言和独立数据库真值。每轮真实写入及复原后以独立 SQLite 验证原状态。串行而非随机，保留阶段漂移，不外推冷启动、MySQL 写事务、大规模 Skill 库或模型费用。
