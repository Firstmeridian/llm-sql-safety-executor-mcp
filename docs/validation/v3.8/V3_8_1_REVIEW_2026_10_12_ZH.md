## 结果解读回放、失败与定点改写

回放文件提供模拟工具定义与返回快照，子代理仅读取夹具、提出模拟动作，未执行写入。MRTR 夹具只提供其描述，但这不是原生 Host 实际筛选工具的证据。Host continuation 的正常对照是继续已有密封请求，不能用缺失续接状态的新工具请求替代。

最初批量 16 场景 × 3 中，三次均给缺失 rowcount 的 P4 补了 1 行；三次均信任 success 字符串异常的 P7；一次 P10 混入另一连接名。失败完整保留。批量要求“场景独立”不等于独立上下文，所以对关键失败再拆为一例一个子代理。

| 关键独立场景 | 原公共文本 | 第一次定点改写 | 最终文本 |
| --- | --- | --- | --- |
| 合法 success=false + committed，rowcount 缺失（P4） | 3/3 没编造行数 | 3/3 明确未报告行数 | 规则继续保留；不能把批量失败说成独立基线失败 |
| success="false" 字符串异常（P7），普通写入 | 0/3 正确 | 1/3 严格合格，另两次有互相矛盾的提交陈述 | 3/3：只说明载荷声称提交，执行未确认 |
| 同一字段异常，模拟只给 MRTR 描述 | 未独立测 | 未独立测 | 3/3 正确，不重试 |

最终改动仅在提示资源：有效性前提先于 outcome 规则，给一条异常字段表达样例；缺失实际行数明确“未报告”，不借用其他请求或预览。合法 false+committed、true+unknown 不被当成格式错误；陌生 error_code／无害扩展字段不覆盖有效 outcome。缺失 outcome、错误目标、预览却报告提交、拒绝后旧状态、注入重试文本、幂等标记与正常首次 execute／Host continuation 的原回放继续保留。

普通描述 **2,706 → 3,546 字符**；MRTR **445 → 2,642 字符**。新预算分别 3,600／2,700；提高 MRTR 预算的原因是必须独立携带规则，不能依赖另一个工具可见。公共文本只维护一份，但 Host 同时加载两工具时会支付两份描述的上下文成本；未额外塞入 instructions 或 sql_assistant。没有本轮固定 token 增量实测，不借用旧 +159 数字描述当前变化。

这仍是行为指导。批量串场误述、其他模型和其他 Host 的行为仍不自动关闭；当前 Host 的最终文本验证只覆盖下述观察范围；server 的授权、令牌、事务与结果字段仍是确定性控制。未建立持久结果台账，也未改变 trusted Python Skill 的边界。
