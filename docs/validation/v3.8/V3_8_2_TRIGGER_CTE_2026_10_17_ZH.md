## 原因与决定

SQLite 对触发器中的物化／常量 CTE COUNT(*) 发出 `READ chosen, column="", database=NULL, source=log_orders`。旧准备流程先要求找到唯一物理对象，尚未处理局部 CTE；已有触发器分析的 CTE／作用域没有参与此分支。

| 原问题 | 本批方案与收益 | 代价／边界 |
| --- | --- | --- |
| CTE 被当作物理表 | 回调外先验证实际来源及片段依赖，再识别局部临时关系 | 增加目录及编译工作；不完整定义、来源歧义拒绝 |
| 只处理 INSERT 会漏纯 SELECT 触发器与 WHEN | SELECT／DML 编译事件均可申请准备来源信息，DENY 后重新准备 | 不在回调内执行 SQL，不枚举全库无关触发器 |
| 重复局部名混合 | 声明保留触发器、片段和 scope 身份；空列 READ 按已验证名称／来源对接受 | 不把局部标签放入全局 ephemeral 集合 |
| 多触发器共用 CTE 名误拒 | 各 owner／片段依赖独立检查后可共享拼写 | 真实来源对象、外层／视图标签冲突仍保守处理 |
| 目录变更后证明过期 | 每请求重新准备，替换为未授权依赖后立即拒绝 | 不引入跨请求授权缓存 |

不同片段的数字 scope ID 不作为全局身份。回调不能提供完整 scope；仅对已完整核验依赖、且所有已附加目录均无同名物理对象的局部 CTE 建立临时证明，来源必须属于相关触发器／片段的已验证来源集合。真实 schema/name READ、写目标及函数独立检查。

有同名物理对象时仍按独立授权及唯一候选检查：无授权拒绝、多 schema 候选拒绝；唯一同名对象也有明确 grant 时可成功。不能笼统写为“同名实体均拒绝”，也不能用 CTE 标签扩大物理 grant。

保持累计 2048 次目录查询、128 个新增准备请求及既有视图图预算；连接锁、总截止时间和清理覆盖重试。仅绑定原 SQL／上下文的非执行型 DML 计划获得编译例外，实际写入仍拒绝。原 SQL、参数、函数限制、可信目录与受管写入边界保持原约定。
