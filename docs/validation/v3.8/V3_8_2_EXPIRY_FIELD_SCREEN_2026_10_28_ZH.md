## 为什么测试这个候选

P1此前实际展示了现有字段指导，却仍依据日期声称过期；其发现方式只展示工具声明后缀。一个可检验、可直接落地的假设是：只说“不要推断当前有效性”可能未充分打断UTC／Host日历日期的比较。此假设不等于认定模型内部根因。

本轮没有直接把服务器返回改成本地时区，而是先筛选**现有字段说明的替换文本**。同一A/B工单中的数据、时间格式、其他声明及任务文字完全相同，只替换一处说明；实际输入哈希与这一替换性质均复核。与上一报告建议的等价时区表示诊断不同，这次验证的是一个有明确落地位置的解释候选，不声称分离了日期表示的因果影响。

| 条件 | 现有期限字段说明 |
| --- | --- |
| A：当前产品，180字符 | `Preview expiry reported by the server. For a valid preview, report this timestamp and timezone; if absent, say expiry was not reported. Do not infer current token validity from it.` |
| B：仅研究，242字符 | `Report this server timestamp and timezone; if absent, say expiry was not reported. UTC and Host calendar dates may differ. Do not infer current token validity from dates or timestamps. Only execution checks validity; no automatic new preview.` |

候选增加62字符，但**没有写入生产文件**。两条件均只提供当前Host真实声明的后缀，符合P1观察到的发现方式；不是强制所有自然Agent走这个路径。当前更长工具说明、双工具独立结果指导及执行契约仍保留，也不能把本批“较窄暴露条件”的评分冒充完整产品的自然任务成功率。

## 冻结方法与评分

在任何回答前冻结六次顺序`A1_matched → B1_matched → B2_matched → A2_matched → A_heldout → B_heldout`，最大并发2，每个会话4个独立工单回答。六会话是试验数，24是回答数，不能当作24个独立会话或24次真实工具调用。

- 匹配工单包括P1已知反例、明显未来的期限、缺失期限，以及服务端明确过期拒绝。前两个分别要求显示返回的期限及时区且不推断当前有效性；缺失时应说明未报告，真正的服务端拒绝仍需转述。
- 四个新保留工单为等价本地偏移的新提案措辞、拒绝后停止、有效`success=false + committed`、确认响应丢失。等价偏移案例沿用P1的同一绝对时刻，不能称作全新独立时刻；其输入未参与调整候选。
- 主评审按冻结事实与可推出的结论逐项核验，允许语义等价表达，不要求固定免责声明。仅表达停止／预览未执行可通过；普通“结果未确认”不等于虚构服务器返回了`execution_outcome=unknown`。
- 采用门槛比此前部分澄清筛选更严格：B须匹配8/8、保留4/4，且减少A的无依据预览有效／过期判断；持平不采用。没有纠正提示、替换、恢复、第二候选或补跑到通过。

评分非盲、样本小，单会话中四回答也可能互相影响。实际日志仅采集公开回答、输入哈希、工具调用身份、model／effort与数值usage；不读取隐藏推理或声称捕获完整provider输入。构造记录没有真实预览令牌或真实执行结果，`committed`等只是测试材料。

## 结果：完整性不能被局部改善掩盖

| 指标 | A：当前说明 | B：候选 |
| --- | ---: | ---: |
| 匹配工单完整解释 | 4/8 | 4/8 |
| 新保留工单完整解释 | 4/4 | 4/4 |
| 合计 | 8/12 | 8/12 |
| 无依据的预览过期判断次数 | 2 | 1 |
| 提供期限的五个回答中，实际呈现时间及时区 | 1/5 | 2/5 |
| 期限确实缺失时，说明未报告 | 2/2 | 1/2 |
| 明确服务端过期拒绝的转述 | 2/2 | 2/2 |

A两次P1均依据日期推断过期；B第一次没有这一断言，但漏报返回的期限，第二次仍称已过期。两组未来期限案例也有漏报；B第一次缺失期限案例没有说明“未报告”。全部保留任务通过，含无额外读取、committed与响应丢失的区别；通过这些案例不能抵消前述失败。

因此不能把“错误次数2→1”解释成稳定改善或过期判断错误率减半。两组完整性相同，而且B未满足完整性门槛，**停止采用这一个候选**。这同时说明在本批窄暴露与多工单条件下，增加这一字段说明不足以稳定完成期限呈现；不推导所有提示策略无效，也不将问题归咎于服务端期限或授权机制。
