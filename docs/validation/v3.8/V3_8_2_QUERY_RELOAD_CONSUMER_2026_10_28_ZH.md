# v3.8.2 实际消费实例发布与子会话门槛（2026-10-28）

本批先验证两版夹具，再冻结三个新的完整双轮任务。**六次本地受控读取与独立真值一致，但三个实际Luna会话均未通过首次原生常量预检，发布及业务两轮没有开始。** 按冻结上限停止、关闭全部会话、清理临时目录，不换会话、不补跑到通过、不要求再次重启。版本仍为v3.8.2，本批没有产品源码／提示／配置／授权变更。

本批原始调用按UTC 2026-10-28归档；文档收尾跨入台北2026-10-29。

## 两版夹具与独立真值

定义先在本批plans目录生成，只有实际部署才进入已配置Skills目录。仅创建三个独占Query目录，不改既有Skill、TOML、grant或业务数据。日期均为半开区间；预检、发布、业务与清理单独编排。

| 任务／连接 | 初版／新版 | 独立真值要点 |
| --- | --- | --- |
| A／analytics_rich_sqlite | 2026年9—10月订单／明细；全状态改为排除cancelled／returned，日期参数更名 | 初版116单／35898.26，新版101单／30623.66；各月订单／明细差额均0，排除15单／5274.60 |
| B／chinook_sqlite | 2025年按BillingCountry发票／明细对账；全盘改为country参数限定Canada，同时更名日期参数 | 初版21个账单国家，新版Canada14票／72.27，发票／明细差额0；国家依据来自发票字段 |
| C／sakila_mysql | 2005年5—6月按租赁月／inventory门店汇总关联付款；新版仅取return_date严格早于2005-07-01，并更名日期参数 | 新版排除6月门店1的一笔租赁及6.99；付款不按payment_date过滤 |

SQLite通过独立只读sqlite3连接取原始行；MySQL8.0.25通过独立PyMySQL只读事务取原始行，再用Python Decimal分组，不复用产品AST、策略或执行适配器作为真值。两版共六次实际应用API受控读取全部一致；不是新的源码全量回归、安装包或原生模型验收。MySQL测试会话sql_mode为STRICT_TRANS_TABLES,NO_ENGINE_SUBSTITUTION，不能泛化到所有版本／模式。

首次本地比对将MySQL的Decimal字符串与浮点真值直接作Python类型相等比较而失败；已改为仅对明确金额字段用Decimal比较，名称、计数、排序和行结构保持严格核对。此为验收脚本修正，保留记录，不算产品失败。两版SQL／定义和业务数据没有因此修改。

## 真实消费会话与有限定位

三个fresh会话实际model／effort均为gpt-6-luna／medium。各自先做精确连接上的`SELECT 1 AS consumer_canary`，成功后才应调用`reload_skills()`及执行级详情；业务提示与第二版参数已提前冻结。实际三次调用均由Host返回：

```text
MCP tool `sql-safety-executor-mcp/query` is not available to the model
```

没有应用结果，没有重载或详情请求，也没有SQL Skill／业务查询、Mutation或配置写入。公开轨迹保留宽泛工具发现和输出截断；这些预检成本没有剔除。三个会话均按要求停止，不关闭恢复或新建替代者；第二版只完成本地校验，没有部署或发布。

| 有限日志核对 | 被检查的manager目录行／保留的SQL事件 | 可推出的事实 |
| --- | --- | --- |
| 前轮两个失败线程 | 26／7 | 两个线程均先使用缓存目录、不等待startup，随后省略没有精确就绪客户端的SQL服务 |
| 本轮三个失败线程 | 40／11 | 三个线程出现同类边界，与各自公开首次调用失败相符 |

仅保留准确线程、原调用标识、有限UTC时间窗及白名单事件类别，不导出原始Host消息、凭据或隐藏推理。关联是线程／窗口级，**并非同一个端到端MCP请求标识**；这些目录事件没有底层握手／进程启动结果，不能在初始化失败、初始化尚未完成、配置代际或客户端绑定之间继续定因。成功主通道也不能证明失败子通道可用。早期成功子会话同样使用缓存目录，故没有依据把清缓存当已证实修复。

本次有限定位已达到停止点。后续仅在取得对应失败请求的初始化／绑定证据，或Host修复／版本变化后，另行冻结新验收；不继续重复同条件试验或要求反复重启。可将脱敏失败边界交给Host维护方；没有自动发送反馈。
