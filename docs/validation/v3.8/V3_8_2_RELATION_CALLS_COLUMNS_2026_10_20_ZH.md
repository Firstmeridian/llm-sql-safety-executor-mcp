# v3.8.2：关系调用身份与 SQLite 生成列补修

日期：2026-10-20；版本保持 3.8.2。对应 DRR-2026-129／130。本批接续前批完整模型验收，运行源码已变化，旧 Host／Luna 结果不覆盖本次源码。

## 变更与决定

| 项目 | 变更前的问题 | 方案与收益 | 代价／范围 |
| --- | --- | --- | --- |
| [功能修复] FTS 调用名称与角色 | 标量别名把 substr、ifnull、char、random、strftime 转为不同关系名；iif／replace 受标量参数规则误拒 | SQLite FROM／JOIN 与表形式 IN 共用具名关系调用解析，保留名称、引用、schema、位置和参数。关系调用头不计为标量函数；参数及子查询继续递归分析，原 SQL 原样执行 | 增加局部方言适配和回归，不全局关闭标量函数规范化，不增加配置开关 |
| [功能修复] JSON 同名 FTS 根 | 保守拒绝实际已授权的 json_each／json_tree FTS5 根，Skill 静态依赖可能为空 | authorizer 按实际 schema／目录模块区分内置 JSON 与具名 FTS；显式授权或已核验视图依赖才能进入对应 FTS 内部能力。Skill 用当前默认 schema 快照补充条件依赖 | 普通同名对象和未授权根仍拒绝；非默认 builtin 限制保持，其他 schema 的 Skill readiness 仍保留已有范围 |
| [功能修复] 生成列元数据 | table_info 漏掉 VIRTUAL／STORED，describe、summary、compact/full 与可查询字段不一致 | table_xinfo 按 cid 返回 hidden=0/2/3，generation_type 标识 virtual／stored；full 保留此字段，compact 以 generated_columns 映射标识，分组签名包含完整元数据 | 返回实际存在的额外列及必要类别字段，payload 可相应增加。hidden=1 不混入默认列和计数，表达式不返回、不执行 |
| [设计约定] 纯分析和目录观察 | 仅缓存表列表不足以复用有条件的虚拟关系事实 | 私有缓存改为 _inferred_analysis，保存不可变 SQLAnalysis；实际存储对象依赖从当前 readiness 快照计算，不缓存目录、授权或可执行结果 | 更新内部测试钩子，公开配置不变；没有通用请求缓存或跨请求数据库状态缓存 |

生成列可读但不能直接写入；生成表达式、UDF 和可信 schema 的执行保障保持其既有边界，本批元数据读取不求值表达式。隐藏的 FTS rank 等字段可在已有授权下显式查询；未列入默认列不等于禁止显式查询。普通列不增加无意义的生成类别字段；MySQL 列投影保持现有契约。索引路径只用 table_info 查主键，当前 SQLite 不允许生成列参与主键，不无差别替换该查询。

## 验证与当前状态

最终全量 **3062 通过／4 可选跳过**，含本批新增 **57 项**；最终类型及源码提示契约通过。独立正常 wheel 安装后 **77 项运行资源** 与源码逐项相同，冻结依赖显式复用，没有全局安装或依赖升级。最终源码／安装各 **538 次 child-stdio 调用**，覆盖 auto／legacy；各含 **420 项独立真值比较**，全部一致。另核验全部工具帧、Skill 可用及执行状态、生成列与 schema 总数。夹具数据库摘要不变，临时目录已清理，私有配置未改动。

新增测试覆盖引用及限定方式、Unicode／空格／点号名称、Skill 发现／详情／执行、main／temp／aux 的实际模块、当前目录变化、真实受限参数和影子拒绝、生成列投影／不求值，以及普通／VIRTUAL／STORED 三类相同列对不错误分组。默认 schema 的条件依赖来自当前 readiness 快照；关闭 schema readiness 时不新增目录探测，执行仍独立核验实际模块与授权。其它 schema 的 readiness 保持既有无法核验范围，不声称静态 executable 保证任何后续状态都能成功。

**维护者重启后，当前驻留 Host 的 12/12 项冻结只读检查全部通过。** `pages` 从重启前的 9 列恢复为原生 SQLite 的 10 列，`status` 标明 `generation_type="virtual"`；compact/full 均报告 34 列并保留生成列类别，FTS 默认列仍只有 title/body 两列。FTS／表形式 IN／标量 substr 与冻结的独立真值一致，SLEEP 参数及直接影子读取继续拒绝，MySQL 常量返回正确。全部实参和返回、列序与拒绝码逐项核对，见[重启补充](v382_relation_calls_columns_2026_10_20/resident_restart/README.md)。重启前 9 列的记录保留，不把状态恢复写成已确认的缓存根因。

重启阶段只验证、更新文档，不改源码、依赖、私有配置／授权或数据，不重复安装／导入及已通过的全量回归。77 项运行资源仍与最终源码／安装记录一致，SQLite 完整文件及三份 TOML 摘要相同，40 份先前封存／1129 条文件记录逐项保持。特殊 FTS 根名称、JSON 同名根及 Skill 夹具的细分正例仍归属源码／安装；本次原生使用现有连接和授权，不外推为全部方言或新的模型任务通过。DRR-129／130 按上述已声明范围完成验收，当前无需再重启。

中间失败保留：类型检查在沙盒内未取得依赖搜索路径，沙盒外通过；完整回归和 child stdio 的沙盒运行停滞后中断，限定命令重跑完成，不确认底层环境根因。首轮新增测试的手工 policy 漏填启用字段，修正夹具；新 typed relation_scope_unresolved 类别遗漏导致通用错误，已补齐。第一轮全量发现条件依赖检查影响 Mutation／独立 readiness 及旧私有缓存测试钩子；收窄到条件依赖、更新钩子后 23 项复验恢复，再跑最终全量通过。一次源码 stdio 在全部检查及落盘后因摘要打印相对路径失败，修正脚本并重新运行最终记录；不掩盖中间失败，也不把它们全部归为环境问题。

## 成本与限制

串行组件 A/B/A 覆盖三类分析、64 列元数据与 16 表列组合；普通表 payload 摘要一致，临时数据库不变。阶段漂移明显：64 列两段基线中位 0.453／1.006ms，当前 0.475ms；16 表基线 5.207／11.309ms，当前 5.830ms。因此不能将合并基线得出的负百分比称为提速，也不能据此给出稳定的退化幅度或延迟保证。本批目的为恢复合法表达和完整元数据，暂不作速度声明；这些是本地组件测量，不是 stdio／Host／模型成本。

固定生成列夹具的紧凑 UTF-8 应用 JSON：describe／summary 各增加 254 字节，compact schema 增加 103 字节，full 增加 208 字节，来自补齐列及类别。该计数不等于 provider token，没有新增模型对照、账单或引导消融。本批不增加 Agent 必需工具轮次或配置开关；不据此前 Luna 的源版本结果推导当前源码任务完成率。

[应用记录、成本原始样本及校验摘要](v382_relation_calls_columns_2026_10_20/README.md)；本地保留完整构建、失败、源码基线与复现脚本，采用独立批次目录。原生结果已在独立重启补充中追加；父检查点的 pending 表示当时状态，旧封存保持原字节。

前置评估的 538 次隔离 Client 调用保留其失败；不是补修后的通过数量。前批 MySQL 81%～85% 提升相对含更早未提交补修的冻结工作区基线，不是 HEAD；本批不扩展性能或 token 结论。驻留结果以本批独立重启补充为准，旧模型证据仍按其实际源码归属解释。
