## 核心契约与实现

同一 `reload_skills` 工具默认只发布 Query，显式 `skill_type="mutation"` 才加载可信 Mutation 入口。候选校验后一次替换活动目录，请求固定自己的目录快照。通过元数据和入口实际字节识别变化，并为新／变更定义分配新的内部代际；手写 `version` 不是执行身份。

| 发布时的状态 | 本批契约 | 验证重点 |
| --- | --- | --- |
| 无变化或仅更新另一 Skill | 复用原对象、代际及未消费预览 | no-op、新增其他对象、Query发布不影响Mutation |
| 变更、禁用、删除，尚未消费令牌 | 移除受影响的待确认预览；本次请求不得靠旧预览执行 | 参数／元数据／源码变更、只失效受影响对象、重放拒绝 |
| 旧请求仍在生成预览 | 签发时比较活动代际，更新已生效则拒绝旧请求签发 | 确定插入点及 MRTR prepare 事件，无 sleep 竞赛 |
| 先消费令牌，后发布新定义 | 允许固定旧代码、计划及绑定值的已获准执行继续 | 托管／命令式执行独立 SQLite 真值 |
| 候选失败 | 活动目录、revision及待确认预览保持 | 导入／计划／定义／缺文件失败及扫描竞态 |
| A→B→A，或删除后重新加入 | 新激活代际；最初 A 的令牌不复活 | 手写version保持不变也拒绝旧令牌 |

签发、消费与发布使用同一锁排序，锁内不导入Python、不访问数据库或等待用户。MRTR的保存审核、重问、批准和拒绝使用同一代际边界；协议能力要求保持。实际数据库结果仍按 `not_executed`／`committed`／`rolled_back`／`unknown` 契约解释，热加载不撤销已获准执行，不把响应丢失当作未执行，不自动重试。

## 取舍、代价与下一步

入口使用读取的同一字节在独立候选模块编译，避开旧pyc，不原地重载活动模块。共享依赖、核心、连接、配置和授权仍需重启；不新增兼容开关、通用确认工具或缓存。未变化对象复用，普通业务不扫描文件；发布扫描有界待确认存储，其成本随条数增长。

可信Python顶层代码会在加载时执行，目录原子性不能回滚它的外部副作用。工具因此标注 `destructive=true`、`idempotent=false`，失败不代表可无条件重试，也不授予业务写入权限。调用Agent应确认回执、实际消费实例的参数／范围，并复用任务所需的获授权业务验证，不为确认而无关写入。

当前没有变更私有配置、授权、已有Skill或样本库。完整原生Mutation变更任务需专用QA授权；草案限定自有SQLite行、精确Skill名单、三个双轮任务、独立真值及部署／预检／业务／清理成本，并预先声明失败停止、不替换到通过。未经批准不部署，也不因双线程条件而绕过重启脚本的进程绑定要求。

契约见[Mutation热加载指南](../../guides/MUTATION_SKILL_RELOAD_ZH.md)。实现取舍参考[Python模块重载说明](https://docs.python.org/3.12/library/importlib.html#importlib.reload)：重载会复用模块字典，已有外部引用也不会自动重绑；本项目因此采用候选入口和固定请求对象。工具注解依照[MCP schema](https://modelcontextprotocol.io/specification/2025-06-18/schema)表达提示，不把注解当作授权保障。
