# v3.8.2 受管写入计划解析器迁移与观察期

日期：2026-10-20。维护者批准独立小范围迁移，并明确选择“保留临时回退及依赖，观察期后移除”。版本仍为 3.8.2。源码／安装及维护者重启后的限定原生验收已完成；历史 FTS／元数据及 Luna 结果保留原归属。

## 决定与变更

| 项目 | 修改前及问题 | 本轮方案／原理 | 收益 | 代价／限制 |
| --- | --- | --- | --- | --- |
| 计划分类 | Skill 加载时以 sqlparse.get_type 分类，忽略目标方言／模式 | 默认 SQLGlot；复用既有会话词法及公开 AST parse，独立检查单个 INSERT／UPDATE／DELETE | 减少默认双解析基础；更早发现部分方言／结构问题 | 解析成功仍不保证数据库语法、对象或业务规则有效 |
| 启动／执行上下文 | 加载时没有具体执行连接 | 启动按 databases 尝试 SQLite 及八组支持的 MySQL 模式候选；目标发现、预览和确认执行前复验实际上下文 | 不把启动候选当目标已通过，避免跨连接套用模式 | 新增目标分类 CPU 工作；首次解析继承模式可能需要初始化连接 |
| MySQL 会话 | 一次探测另一连接不能保证写连接相同 | 沿用每物理连接初始化／核验完整 sql_mode 的既有约定，包含重连／池重建 | 实际执行会话遵守相同契约 | 无新增逐请求模式查询；HIGH_NOT_PRECEDENCE 在新路径仍明确拒绝 |
| 原始语句契约 | REPLACE 与 INSERT OR REPLACE 可被归一成相近 AST | 结合原 token 的主语句动词及根 CTE 名字位置；拒绝嵌套写 AST | 保留原“直接 INSERT／UPDATE／DELETE”边界，不意外放开 bare REPLACE | 不是通用 SQL 正确性证明，不执行 AST 生成 SQL |
| 注释 | MySQL 条件执行注释可能被解析器略去 | 新路径复用既有注释事实，拒绝执行型／hint／歧义注释，保留普通注释和字符串样文本 | 避免单语句判断忽略服务端会执行的内容 | 受管模板中的 hint 也保守拒绝，需维护者审阅改写模板 |
| 确认期复验 | 缓存计划启动后不再按实际语义分类 | 消费令牌后、adapter 写调用前复验；失败返回 managed_plan_validation_failed／not_executed | 不写入，已消费令牌仍不能重放 | 正常确认多一次分类；不会恢复消费后的令牌 |
| 临时回退 | 维护者希望保留观察窗口 | `[skills.mutation] managed_plan_parser="sqlglot"` 默认，可显式改为 `"sqlparse"`，需重启 | 可定位迁移行为差异 | 两套实现／依赖暂存；不自动降级，旧路径不具备新方言／注释检查保证 |
| 公共写入规则 | 计划字段、值来源、精确命名绑定和事务结果独立存在 | 保留共用校验、原 SQL／参数、批准、预览、令牌、行数回滚及提交证据 | 原有写入边界和业务过程保持 | 不把 raw 读取 allowlist／authorizer 当作写入批准；可信 Python 副作用仍不在计划分类范围 |

不新增 parser 私有覆盖、运行依赖、authorizer 关闭选项或 Agent 必需调用步骤。不修改私有 TOML、配置数据库业务数据或现有授权。真实扩展／测试替身必须履行既有 resolve_analysis_context 接口，不加缺接口时猜方言的兼容层。

## 固定语料与对照

基线是 HEAD `2c0a9e7` 之后、已完成读取能力／元数据／FTS 补修的实际未提交源码，**不是仅检出 HEAD**。修改前保存 76 项运行资源摘要及源码归档；固定两份实际受管定义、98 条 SQL 和十个上下文：SQLite、ANSI_QUOTES／NO_BACKSLASH_ESCAPES／PIPES_AS_CONCAT 八种组合，以及 HIGH_NOT_PRECEDENCE 拒绝控制。实际内置计划只有两份且 SQL 相同，不将它们夸大为多样生产写入样本。

最终比较两个完整计划校验器，计划字段、SQLAlchemy 命名绑定目标和值来源相同，共 **980 组**：

| 结果 | 组数 | 解释 |
| --- | ---: | --- |
| 两者接受 | 593 | 包括两份实际计划在九种受支持上下文中的全部 18 组 |
| 两者拒绝 | 173 | 包含非计划语句、多实际语句、bare REPLACE 等原边界 |
| 旧拒绝、新接受 | 27 | 三种 DML 的末尾块注释，在九种受支持上下文中恢复；无新业务能力绕过 |
| 旧接受、新拒绝 | 187 | 78 组属于 HIGH_NOT_PRECEDENCE 控制；其余 109 组包括方言不符、部分非法／嵌套结构、位置绑定等 |

SQLite 同 98 输入分别以独立 sqlite3 的 EXPLAIN 编译，前后完整 dump 相同。保留“SQLGlot 能接受而 SQLite 仍报错”的样本，例如不完整 SET 结构；解析不能取代数据库校验。位置参数 SQL 即使原生能编译，也不等于现有命名绑定传输契约支持它；不因迁移改写绑定接口。六个后加注释控制单独列为 supplement，不算进最初冻结 98 条。

最初 prototype 对比的是“旧完整校验器／候选分类器”，仅作设计探针；最终版本才是两个完整校验器。两份结果均保留，不混用口径。首轮新测试错误地把重放拒绝视为普通结构化结果、把 meta 字段视为业务字段，已按实际接口校正；完整回归首轮两个替身缺少目标上下文接口的失败也保留，未放宽生产检查。

## 重启后限定原生验收

维护者确认当前Codex通道重启后，先执行SQLite常量调用，再按冻结输入逐项核验。两份内置计划在rich_mutation_sqlite均成功预览：订单1仍为confirmed，更新目标shipped、复原目标pending的原SQL和绑定值正确，返回not_executed并签发一次性句柄。倒退转换返回validation_failed及同目标可用复原Skill；未准入MySQL连接在发现、详情和预览入口一致限制。MySQL大小写CTE、FTS读取及函数／影子访问拒绝也符合预期。

原冻结预期15/16：搜索规则包含related_skills，而最初只预期返回update，遗漏了引用它的reset。保留原预期及失败，用独立勘误校正后16/16通过；没有源码修复或重复原生调用。独立只读SQLite复核两个文件摘要、80行完整订单摘要和前12项状态不变，FTS计数为4；先前17份清单／435文件相同。

两份提案均放弃确认；当前无公开撤销预览工具，按300秒TTL自然过期，不声称主动撤销或已观察过期。句柄在落盘前从文本／结构化字段一致脱敏。本次仅当前Host应用结果，不是双协议、完整协议帧或原始字段省略的证明。维护者重启确认与行为核验不等同驻留源码摘要证明；特殊上下文切换／提交／回滚保留源码和安装覆盖，无新完整模型试验。原生补充不需要新增授权、配置或再次重启。

## 端到端及合法拒绝补测（2026-10-20）

维护者追问后，以同一实际基线／当前默认／实际基线串行A/B/A补测完整stdio成功流程：每周期六次调用（发现、详情、更新预览／提交、复原预览／提交），每阶段8轮预热＋40轮计时，两协议共1440计时调用和288预热调用。288个周期全部成功且临时SQLite独立行真值复原。**完整流程有小幅可测退化**：现代协议49.49→54.89ms（+5.40ms、+10.9%），legacy90.67→95.18ms（+4.52ms、+5.0%），均相对各自两阶段基线周期合并中位数；周期是六次工具往返耗时之和，不含初始化、模型思考／本地编排和独立真值检查，不与先前微基准混用或外推所有负载／MySQL写入／模型token。

独立非计时仪器在六次调用中记录11次受管分类：目录2、详情1、两个预览及两个确认各2。说明有重复工作；其全部时延贡献尚未独立隔离。建议按固定计划／解析器／实际会话指纹复用纯分类结果，每次仍核验目标语义、授权和令牌。本补测没有实现缓存或改变生产源码。

能力不能笼统称为零收窄：新增18个独立SQLite／MySQL非执行计划全部可编译，其中6组被新策略有意拒绝：两种数据库的hint形注释各1，以及HIGH_NOT_PRECEDENCE会话4个控制（含没有NOT的简单UPDATE）。这些不是数据库非法语句，存在精细化支持余地；与冻结矩阵中真正的方言／格式／绑定问题分开。普通注释／字符串样文本和六种MySQL修饰语继续接受，现有两份内置计划及已测业务成功路径没有回退。

建议优先减少重复分类，然后分别评估hint／HIGH_NOT_PRECEDENCE细化；保留可执行注释拒绝和实际批准边界。观察期回退仍显式选择。这里只提出后续建议，没有实施优化或修改支持范围；DRR-119限定验收及旧封存保留。[详细时延、差异、脚本和证据](v382_managed_parser_2026_10_20/performance_followup/README.md)。

## 观察期退出条件与遗留项

1. 维护者选择保留临时回退及依赖，建议在两至三个后续发布检查点复审；这是评审窗口，不是自动过期或保证某版本移除。
2. 实际模板、独立边界语料、SQLite／现有 MySQL 模式及源码／安装／重启核验保持通过；新增真实需求单独记录差异，不能通过自动回退掩盖 SQLGlot 失败。
3. 未出现必须新增复杂私有适配才能支持的真实受管计划；比较异常、额外分类成本和扩展接口影响后，由维护者确认删除 selector、旧实现、双路径测试及 sqlparse 依赖／锁文件条目。
4. 此 selector 只回退受管写入分类，不回退整个 SQLGlot 库或读取解析器，因此不代替库升级回滚。B32 的两套实现及既有私有 API 维护风险仍未全部消除；本轮没有新增 `_parse_*` 定义，现有 14 个定义包含项目辅助方法，不能一概称为 14 个上游覆盖。
