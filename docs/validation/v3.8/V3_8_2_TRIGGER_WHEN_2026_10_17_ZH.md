## 改动、原因与代价

| 之前 | 本批方案 | 收益与边界 |
| --- | --- | --- |
| 取表名后首个 BEGIN token，误读 WHEN 内的 NEW.begin／OLD.begin | 先识别可选 FOR EACH ROW，再由 SQLite SQLGlot 表达式解析消费完整 WHEN，要求下一个 token 是正文 BEGIN | 名称、CASE、函数、子查询和 CTE 内的 begin 保持其角色；不引入通用解析框架 |
| 恢复误拒可能误跳过 WHEN／正文依赖 | 表达式入口只定位边界，随后仍按原始 WHEN 和每个正文片段做共享完整分析 | 未授权来源／目标、受限函数及实际 DML 保持拒绝；原 SQL 与绑定值不重生成 |
| 部分无效区域可被错误分片 | 核验 FOR EACH ROW 的非引用关键字、非空条件与真实正文标记；不支持定义继续拒绝 | 不将失败分析当成没有依赖，不跳过整个条件 |

新增成本是在需要准备的触发器 WHEN 上多做一次表达式解析；没有新增数据库探测、grant、配置、依赖或 Agent 必需步骤。连接独占、回调无 SQL、累计目录／重试预算与总截止时间保持原执行边界。SQLGlot 解析扩展随其既有固定版本维护，升级时须重验。未做新的服务器／模型成本 A/B，不宣称零延迟。

## 失败 Agent 试验：已确认的链路

原始完整业务试验仍为 [2/3](V3_8_2_ADJACENT_AUDIT_2026_10_17_ZH.md#复杂完整的-agent-任务)。失败子会话 ID 为 `01a14994-d166-7682-95cc-06df68495191`，Codex 版本 0.163.0。其正确名称的 list_tables 调用没有正常 SQL MCP 应用结果，随后目录为空。

本批只读检索本机 Codex `logs_2.sqlite`，限定原三个试验线程、90 秒时间窗及 `codex_mcp::connection_manager::tool_catalog`，没有导出用户其他对话、凭据、模型隐藏推理或全库日志。结构化记录确认：

| 时间（UTC） | 失败子会话的 Host 记录／公开结果 |
| --- | --- |
| 11:17:41、11:17:47 | using cached MCP catalog without waiting for startup；SQL 工具名可见 |
| 11:18:00 | omitting MCP server without an exact ready client；公开调用返回 Host unavailable |
| 随后两个步骤 | SQL 工具目录为空，两个业务轮次未完成 |

这比先前只有应用轨迹更明确：**Host 复用了缓存工具目录，实际匹配且就绪的客户端却没有跟上，随后服务被省略**。成功子会话也有缓存目录复用记录，因此不能把缓存本身或“旧缓存没清”直接定为根因。日志没有解释底层为何没有 exact ready client；初始化失败、初始化时序、配置／绑定竞态仍不能细分。模型工具拼写错误和 SQL 策略拒绝不符合该失败轨迹。

上述修复前 Host canary 只诊断可调用性，不是完整销售任务，也不覆盖 WHEN 修复的驻留行为。恢复线程的累计业务历史只作为原始参考，公开诊断单独切分；先前两次业务轮次失败不重复统计、不改成成功。所有诊断均只读，没有由 Agent 重启 MCP 或修改用户级配置。维护者重启后的新完整任务另见下节。

建议按以下顺序处理：

1. 在实际待测子会话读取选中工具的参数说明，使用已确认别名做一次真实 canary。另一个预检会话成功不能替代它。
2. 遇到 Host unavailable／目录消失，保留失败，关闭后恢复该会话或新建一次，再验证；设定有限次数，不无限重开直到只剩成功样本。参数校验错误单独纠正，不当作客户端未就绪。
3. 对 SQL MCP 是必需能力的工作流，可评估在现有 Codex SQL MCP 节设置 `required=true`，让初始化失败提前显式失败。本批未做该配置 A/B，不能宣称它修复了原始内部故障，也未自动改写用户级 Host 设置。
4. 当前没有依据盲目增加启动超时：本机默认 10 秒，沙盒外启动约两秒，沙盒内增至 60 秒仍失败。若再次复现，保留同一线程、时间与底层启动／握手日志，再定位初始化或绑定环节。

[官方 MCP 文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)规定启动超时默认 10 秒，required 控制初始化失败时的启动失败语义；optional startup grace 控制初始目录等待。[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)提供对应设置。这些解释设置的用途，不能替代本机故障根因证据。本地可审阅的配置片段和恢复步骤在 `local_archive/v382_review/handoff/codex-sql-mcp-readiness.md`，不随包发布。
