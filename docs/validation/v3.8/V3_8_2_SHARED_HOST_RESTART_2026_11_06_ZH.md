# v3.8.2 受控共享 Host 重启

日期：2026-11-06。基于 `cf11c51` 工作区；与此前范围引导／读取性能改动分别验收。

## 目标与约定

维护者批准显式共享 Host 模式，解决同一 Host 加载多个空闲聊天时，默认单聊天模式无法重启当前消费者的问题。默认严格模式保持；`--allow-shared-host` 仅适用于 `restart` 与只读 `verify --check-process`，与全目标组模式互斥，不扩展 `recreate`。

实际消费者 PID 与 Linux 直接子进程、启动时刻和精确启动定义绑定；要求至多八个同工作区消费者一一对应，其它聊天空闲。只向当前聊天独占进程发送 SIGTERM，之后至多请求一次 Host 全局刷新。停止前、刷新前复核范围；不能将共享 PID、目录不可用、配置漂移或范围变化解释为可自动扩大的维护授权。

这是主动停止范围的收窄，**不是全局刷新的跨聊天隔离**。其它消费者是否复用或替换分别报告。检查与发送不原子，空闲不能证明不存在待确认预览；维护者随后授予固定低风险维护授权：其它聊天空闲、无在途写入／等待结果且接受可能重新预览时，提醒后执行，不逐次请求批准；以操作状态而非CLI／其它界面判断。出现未决写入、具体不明状态或范围变化仍暂停。停止成功后如范围变化，会停止刷新而可能暂留当前服务不可用，需要人工决定恢复。

## 验证层次

实现与现场验收分开记录。隔离测试使用假 Host 和自有子进程，不接触真实服务；既有严格／组／恢复路径也需通过回归。沙盒不能创建 Unix 套接字导致的失败保留为环境限制，不算产品缺陷或通过。

本轮隔离测试、只读现场预检及最终现场状态见下方追加记录；未完成真实重启时，不宣称共享 Host 路径已现场通过。

### 隔离回归与只读预检

- 完整辅助选择集 **230 项通过**，其中新增共享模式27项；旧严格／组／恢复、绑定、就绪及版本清理路径保持通过。自有进程实测只收到一个目标 SIGTERM，另一消费者保持存活；所有自有进程均清理。
- 最初在沙盒运行旧选择集89项时，35项因 Unix socket bind 权限失败、54通过；同一89项沙盒外全部通过。该失败不归因于 Host 缓存或实现变更，完整230项亦在沙盒外完成。
- 当前只读 `verify --check-process --allow-shared-host` 通过：唯一绑定 Host，两个同工作区消费者一一对应，另一聊天为空闲；两个目录／常量读取均通过。`process_signals_sent=0`、`reload_attempted=false`，没有配置或业务写入。一个其它候选端点仍握手失败，不妨碍已经证明的唯一当前线程绑定，也不把它写成根因已修复。
- CLI 参数、语法及 diff 格式检查通过。该次只读预检结束时尚未真实重启；其后维护者授予固定低风险维护授权，后续现场操作另记。只读通过不保证未来状态不变。

### 固定授权下的一次真实重启

维护者澄清接受同 Host 的 CLI／其它界面都可能受刷新影响，并授予上述固定低风险维护授权。再次只读复核通过，当前轮未发起业务写入，也没有已知未决写入；另一聊天的 Host 状态为空闲。提醒后仅执行一次限定重启，没有再次索取相同范围批准。

| 核验 | 结果 |
| --- | --- |
| 信号／刷新 | 1 个当前目标 SIGTERM，确认退出；1 次 Host 全局刷新，没有追加重试 |
| 当前消费者 | 实际 PID＋启动身份已替换，且不属于原目标集合；新目录及常量读取通过 |
| 另一原消费者 | PID＋启动身份保持，常量读取通过；本次未观察到进程替换，不推广为以后均无影响 |
| 当前 Agent 通道 | 原生 SQLite／MySQL 读取及新版范围拒绝说明通过；不是仅控制端目录或退出码成功 |
| 配置与业务副作用 | 无配置／grant 修改、无业务写入；未启用组停止、recreate、桥接或线程迁移 |

刷新后的消费者核验窗口约 3.249 秒，是本次脚本记录的局部窗口，不是整体重启耗时或稳定性能保证。原只读预检与230项隔离结果保留原归属。现场回执、更新后的限定计划及固定授权记录保存在本地分层归档；[公开清单](evidence/shared_host_restart_20261106/manifest.json)和[压缩应用证据](evidence/shared_host_restart_20261106/records.json.gz)不包含凭据、业务预览令牌或隐藏推理。

配套的8组／14次原生产品核验通过；两项实际 Luna-medium 只读任务中，一项正确澄清，一项未完成目标连接恢复。这些是独立的产品／模型结果，不用来扩大本脚本的成功范围，见[产品报告](V3_8_2_SCOPE_READ_PERFORMANCE_2026_11_05_ZH.md)。

## 开发辅助增补：维护互斥与诊断回执

在上述现场验收后，维护者另批准三项小范围改善：按绑定 Host 控制端点取得非阻塞
`flock`，为失败回执提供 `next_action`，并记录 `timings_ms`。所有维护路径持锁至必要
配置清理和最终日志结束；只读路径不加锁。锁文件不删除，进程退出释放系统锁；
它只协调同端点的本脚本，不控制人工维护或 Host 行为，也不替代范围复查。

- 新增 **28 项**关键契约测试，合并原选择集后 **258 项通过、零跳过**。覆盖真实隔离进程竞争／退出释放、只读可用、失败及日志关闭前持锁、锁后预检错误归因、失败计时、配置清理与原截止预算。
- 最终版本对当前真实 Host 的只读 `probe` 与 `verify` 均通过；不发送信号／刷新，不改配置或业务数据。两次较早的只读记录另存为实现阶段观察，最终回执单列。这些不称本批又完成实际重启，也不覆盖此前230项与一次真实重启的证据身份。
- `next_action` 只是说明，不执行恢复、不授予权限。已发刷新但未确认时建议只读检查；配置恢复不证明运行状态恢复，不追加刷新。
- 计时只表示脚本自身窗口，失败也记入；两次刷新 RPC 耗时累加。`total` 截止于连接清理后的回执快照，最后日志落盘、锁释放、输出序列化及正常 CLI 解析／发现不计入。阶段不是完整分解，不据此归因 Host 内部耗时或宣称性能／token 收益；60／30秒预算不变。

最终源码、测试及脱敏回执见[增补清单](evidence/maintenance_helper_20261106/manifest.json)与[压缩记录](evidence/maintenance_helper_20261106/records.json.gz)。机制依据为 Python 的[文件锁](https://docs.python.org/3.11/library/fcntl.html#fcntl.flock)和[单调时钟](https://docs.python.org/3.11/library/time.html#time.monotonic)约定，不增加第三方依赖。本地细目在 `local_archive/v382_review/20261106_restart_maintenance/`。工作流说明迁到测试 §4.5，Query／Mutation 热加载操作从该开发辅助段移除。

## 成本与限制

维护时增加其它消费者的目录／常量／PID 核验；普通业务请求没有新增字段、调用或延迟。复用既有进程守卫、pidfd 和受限就绪等待，不增加依赖、后台监听或新的 Host。受支持配置更窄：已有 Linux WebSocket Host、同工作区、每聊天独立且完整匹配的目标进程；不支持无可绑定控制端的 VS Code 插件，也不恢复已撤回桥接。

Codex 官方将 `config/mcpServer/reload` 定义为重新读取配置并为加载线程排队刷新。请求受理不代表新消费者就绪；已安装 0.166 的实验 schema 与此全局范围一致，没有单服务刷新参数。[OpenAI App Server 文档](https://learn.chatgpt.com/docs/app-server)

操作见[中英文重启指南](../../guides/CODEX_MCP_RESTART_ZH.md)；本地计划和脱敏证据位于 `local_archive/v382_review/20261106_shared_host_restart/`。本批没有性能／token 改善声明。
