## 实现与约定

| 项目 | 变更前 | 本批实现／收益 | 代价及限制 |
| --- | --- | --- | --- |
| 目录投影 | SQLite 为全部合法、已授权表估算，再由工具截断 | get_table_directory 返回表名及廉价目录估算；两个公开工具先授权、保持目录顺序、统计可见总数、截断，再 enrich_row_estimates。50 表只返回 5 张时，只做 5 张表的估算 | adapter 新增明确的目录接口；真实第三方扩展需实现，不添加接口探测兼容层。目录本身仍会枚举，total_tables 保留可见总数。 |
| SQLite 统计 | 每表检查 sqlite_stat1，再每表单独执行一次统计查询 | 每次补全只检查一次；选中名称每 200 个一批绑定，单条固定 VALUES／相关标量查询返回每表至多一行。单表 describe／summary 复用同一实现 | 相关子查询保留每表原有 LIMIT 1 选择方式，避免全部索引统计拉回内存；不承诺数据库只扫描一次统计表。不引入跨请求缓存或多语句原子快照保证。 |
| 缺失／无效统计 | 缺统计时受控计数；异常统计值处理不完整 | 缺条目、空／损坏／负值逐表回退受控限量计数；统计表在存在性检查后消失也回退。超时等其它数据库错误仍是 metadata_query_failed | 合法零估算保持 0；null 仍为未知。数据读取继续全套方言分析、目录准备、authorizer 和超时检查；本批没有降低该成本。 |
| SQL 传输准备 | 没有现成分析时，即使 SQL 无冒号也进行分词及逐字符重建 | 无冒号直接构造 SQLAlchemy text；带冒号仍用原路径，保护业务名称、字符串／注释冒号和真实绑定 | 仅传输层快捷路径，不是策略放行。带绑定的列元数据等仍可能分词；不增加纯分析缓存或目录缓存。 |
| MySQL | 目录查询一次取得 TABLE_ROWS | 新目录接口保留一次 INFORMATION_SCHEMA 查询，补全直接复用已有结果 | 不额外按表查询，不改变临时对象或可信会话处置边界。 |

get_tables 保留完整目录加补全的内部便捷入口，因此既有直接适配器调用仍能取得完整估算；公开工具选择新分阶段接口。get_read_relations 的 table/view readiness 契约保持独立，不能用表发现替代。空投影不检查统计或读取数据，未授权对象不会被采样；元数据补全失败仍明确失败，不伪造空数据库。

只对返回表估算也意味着：未返回对象的估算失败不再影响本次工具，total_tables 仍计入那些可见对象。每个统计批次沿用一次查询超时，不扩大预算；在极大的统计表上，相关子查询的实际数据库工作量仍需单独评估。

统计按解码后的完整表名绑定，不 trim／Unicode lower／拼接 SQL 名称。main 统计和受控计数都固定 schema，temp／aux 同名对象不替代目标。没有新配置项、依赖、grant、版本提升、Agent 必需工具步骤或提示词修订。纯分析缓存、目录准备复用和批量列读取均未在本批实施。

SQLite 的 stat 字段是索引／表统计；同表多条统计、尤其部分索引，不能被解释为精确业务总行数。本批保留先前的每表第一条观察语义，并增加对照，不擅自选择另一条“更像真值”的统计。[SQLite sqlite_stat1 格式](https://www.sqlite.org/fileformat.html#the_sqlite_stat1_table)。每批绑定 200 个以控制变量／返回数量，未依赖本机较高的变量上限；测试将连接上限主动降为 200。[SQLite 限额](https://www.sqlite.org/limits.html)。

SQLAlchemy text 使用冒号名称绑定；没有冒号时省略这部分词法识别具有明确前提，不能推广为任意 SQL 的授权捷径。[SQLAlchemy text](https://docs.sqlalchemy.org/en/20/core/sqlelement.html#sqlalchemy.sql.expression.text)。
