## 问题与处理

外部评审指出：常规测试实际加载根目录演示 Skill，但发布脚本的指纹没有包含这些文件。独立复核确认，编辑、新增或删除 Skill 后，比较仍会报告没有变化；同样遗漏了测试实际加载的静态 SQL／Markdown 夹具。这是既有的验收身份缺口，不是已确认的产品授权或事务缺陷。

| 项目 | 补修与依据 |
| --- | --- |
| 根目录 Skill | 将 `skills/**` 的 `.py/.sql/.md` 纳入既有 `validation` 指纹；包含入口、SQL、定义及引用 Markdown |
| 静态夹具 | 将 `tests/fixtures/**` 的 `.sql/.md` 纳入；该目录下 Python 已由原有递归测试文件规则覆盖 |
| 比较与结束检查 | 编辑、新增、删除均改变身份；沿用原 `validation` 变化的全场景复核建议，以及 fast／release 的结束比较，不增加第二套身份结构 |
| CI 触发 | `push`、`pull_request` 均增加 `tests/fixtures/**`；根目录 `skills/**` 已有触发规则 |
| 范围 | 不收集 bytecode、审计日志或私有连接 TOML；不新增依赖、缓存、监听或运行时调用步骤 |

实际消费路径也已核对：`test_mutation_guarded_reads_v382.py` 从仓库加载两个演示 Mutation；`test_multi_connection_v35.py` 与 `test_v342_meta_and_schema.py` 使用 `tests/fixtures/v37_scoped_skills`。覆盖当前已知静态输入，不声称自动识别未来任意类型的测试资产。

## 11月7日提交前复核：目录链接身份补齐

独立审阅发现相邻P2：`rglob()`没有递归进入目录符号链接，原指纹也未记录链接目标。当根内`_deployment/A`、`B`都已存在，活动Skill从A改指向B时，实际加载SQL改变，但普通文件集合和内容哈希不变；模拟release结束检查会误报通过。这是验证身份漏检，没有新增确认产品授权或事务缺陷。

沿现有扫描记录目录链接（含输入根）及悬空链接的目标身份；选定后缀的文件链接同时记录目标与内容，普通文件保留内容哈希。继续不递归跟随目录链接：受支持Skill须保持根内，已有普通部署文件仍由原扫描覆盖。不新增目录监听、通用遍历框架或生产检查，起止A→B→A的限制保持。

新增五项检查：根Skill／静态夹具的链接新增、改向及删除；fast／release运行期间改向；文件链接内容控制。补修前四项命中目标失败、控制一项通过；补修后核心83项通过，含合法根内Query／Mutation目录链接的扩展组254项通过、零跳过，后者包含核心，不相加。最终扩展组沿用已验证的沙盒外环境、90秒预算，实际12.06秒；无新的环境重试、Host刷新或配置库操作。
