## 变更与取舍

| 项目 | 原问题 | 本批方案／收益 | 代价及边界 |
| --- | --- | --- | --- |
| DRR-116 | FTS 外部内容是含受限函数的视图时，可信完整投影预热的模块内部 SQL 可在后续受控读取中继续求值，却不再触发函数编译回调 | core/read_rules 提供共享的受限函数事实判定；原始读取策略、SQLite 回调和回调外的视图／触发器准备使用同一规则。每请求检查已完整分析的可达视图定义，再允许执行 | 保守检查整个可达定义：即使只选普通列、做 COUNT 或 SQLite 能剪枝，定义含保留函数仍拒绝。未新增解析／目录步骤；增加对已有函数集合的检查，不承诺零成本 |
| DRR-117 | 明确授权 aux 具名 FTS 根后，普通 MATCH 成功，等价表调用／IN 被误套内建函数默认库限制 | 默认 schema 限制只适用于 VirtualRelationUse.kind=builtin；sqlite_named 保留实际 schema/name 授权及 FTS 模块／影子身份核验 | all 仍仅默认 schema；不开放其它模块，不向用户授予内容／影子表，不把非默认 schema readiness 标成已核验 |
| 相邻边界 | 仅测 SLEEP 冷态不能证明预热、其它保留类别或不同工具入口一致 | 补文件、锁、耗时、账户、PRAGMA 函数类别，以及真实 PRAGMA 关系、两协议、冷／列元数据／可信完整预热、定义替换、Unicode 正例、正常派生内容视图和错误 schema 拒绝 | 测试替身只计数并返回固定文本，无延时、文件读取或外部副作用；临时夹具自动清理 |

不把完整 raw 查询策略套进视图：已批准视图可有派生关系，其底表依赖不需要另变成直接 grant。直接读取未授权底表／影子表依然拒绝；普通函数、业务列名、字符串及 Unicode 业务名称保留。共享函数判定只复用结构化事实，原 SQL／参数、连接独占、目录限额、回调生命周期和异常清理保持。

原 SQLite authorizer 只在编译／重编译时判定，并非每次函数求值都回调；关闭 Python DBAPI 语句缓存不能推出 FTS 内部缓存也被清空。[SQLite authorizer 官方说明](https://www.sqlite.org/c3ref/set_authorizer.html)。FTS5 外部内容可来自表、虚表或视图，因此必须递归检查实际内容对象，不能把 FTS 根存在视为所有操作都允许。[FTS5 外部内容说明](https://www.sqlite.org/fts5.html#external_content_tables)。

schema、已安装 UDF／扩展继续是可信部署内容。本修复覆盖可达视图中已分析的保留函数，不证明任意 UDF 无副作用，也不新增对物理表生成列表达式的完整执行沙箱；已有生成列编译回调局限保持明确。不提供 authorizer 关闭开关。
