## FTS 的实际边界

FTS5 内部与直接 `PRAGMA main.data_version` 的回调参数实测相同；source 不是模块来源证明。本修补明确依赖两层：先按原始 SQL／分析上下文核验全部直接关系，再在核验根的生命周期内赋予限定内部能力。影子对象须同时匹配已核验模块的存储名称与实际 shadow 类型；external-content 按实际 schema 和完整名称解析，不拆名称中的点号，仅读取 FTS 声明列及 content_rowid。使用 FTS 不授予直接读取内容／影子表的权限。

每请求重建能力，不跨请求缓存授权；回调仍保持至结果消费、可能重编译及清理结束。模块自己的预编译缓存可能跨请求存在，故不能用 cached_statements=0 或预热后成功证明全部内部动作每次重报。所有直接根在每次执行前复核，内容视图仍展开并检查受限函数；异常后清空上下文。可信 schema／UDF／Python 扩展边界保留，不把该设计说成任意虚表模块沙箱。[SQLite authorizer](https://www.sqlite.org/c3ref/set_authorizer.html)、[FTS5 external-content](https://www.sqlite.org/fts5.html#external_content_tables)、[回调来源定义](https://www.sqlite.org/c3ref/c_alter_table.html)。

### `main.pages_fts` 根授权的含义

`main` 指 SQLite 主库；`pages_fts` 是 Agent 直接请求读取的 FTS5 对象，“根”指依赖图的入口，不是超级用户或文件系统 root。现有 relations 中新增这一个组件身份，允许裸名和 `main.pages_fts` 两种等价引用，支持普通读取、MATCH、排名和计数；不是仅限某个搜索词的权限，也不自动限制为已发布页面。

服务端核验此根后，可为该次请求提供 FTS 必需的内部影子／内容列及只读 data_version 能力。Agent 不能据此直接读取影子表或全部内容表；若内容表本来另有显式授权，则该直接读取由原授权决定。发布筛选是任务 SQL 的条件，写入仍有独立权限和审批门槛。本次仅追加这一条私有读取配置，没有写数据库。
