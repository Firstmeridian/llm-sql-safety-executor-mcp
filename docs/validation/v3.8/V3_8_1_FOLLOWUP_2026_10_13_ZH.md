## 决议与契约

项目尚未正式发布。旧 `.env`、旧启动入口、旧 SDK 迁移及假想历史调用方兼容，不纳入修复范围；更好的设计应主动说明收益、受影响接口、验证与文档范围。当前实际使用的 Host、SDK 与 Skill 必须同步验证。此次内部接口直接调整，没有增加旧元组／错误字符串兼容层。

| 层 | 当前契约 |
| --- | --- |
| SQL 判定 | `PolicyDecision(allowed, error_code, message, hint)`；raw query、Query Skill 启动／发现／执行复用；`is_sql_safe()` 为该语句分类器的布尔便捷函数 |
| 适配器读取 | `execute()` 成功返回 list，失败抛 `DatabaseQueryError`；禁止以 `Error:` 字符串判断成败 |
| 工具读取失败 | SQL／策略失败返回 `success=false`、固定 `error_code`、安全 `error`，按需附 `hint` 和已解析的 connection_id/db_type；Query Skill 另有 skill_name |
| 操作异常 | 参数、未知连接／Skill、Skill 范围、profile 与 schema readiness 等错误仍可表现为协议 ToolError；未知连接给出 list_connections() 提示 |
| 内部 metadata | 读取异常转为 MetadataQueryError；索引失败仍保留列并返回 unavailable/null |
| 写入 | 不用查询错误类别推断 committed/rolled_back/unknown；原事务结果、审批、令牌与审计边界继续独立 |

授权的 SQLite 裸表 IN 保留；限定名要求精确限定的 allowlist 条目，不能用 basename 授权另一 schema。可识别的 IN 表值函数按虚拟对象名授权，参数中的子查询仍检查；FROM 函数／引号函数等原有未支持形态仍可能被拒。CTE 精确匹配及非递归自引用／前向引用的物理表检查保留。UNION 规则作用于真实运算符，包括递归 CTE 内的 UNION；WITH RECURSIVE 关键字本身不被一律禁止。

数据库读取错误的固定类别如下；未知驱动错误使用通用类别，不按异常中的任意 SQL 文本推断原因。策略类别由 `PolicyDecision` 给出，例如 `multiple_statements`、`union_disabled`、`table_access_denied`，与下面的驱动错误分开。

| error_code | 含义／恢复 |
| --- | --- |
| unknown_table / unknown_column | 表／列不存在；同一连接调用 list_tables／describe_table |
| unknown_function / invalid_function_arguments | 方言不支持函数／参数不正确；按返回的 db_type 调整 |
| incomplete_sql / sql_syntax_error | 语句不完整／语法错误；补齐或按方言修正 |
| query_timeout / database_locked | 查询超时或中断／数据库锁冲突；不据此推断写入 outcome |
| database_read_only / database_access_denied | 数据库只读／数据库权限拒绝 |
| database_connection_failed / database_connection_lost | 建连失败／执行时连接丢失；不把丢失连接说成超时 |
| database_query_failed | 未识别的读取失败；不编造具体原因 |

方言 AST 解析器仍是可报告的更好设计候选；本轮复用现有作用域解析并收敛重复规则，没有足够语法覆盖／性能证据支持直接替换依赖。若继续出现复杂解析分支，应另做代表查询集对比，不因发布前兼容顾虑避开替换。

### 新确认：Skill 自动依赖把 SQLite CTE 当成实体表

```sql
WITH F AS (SELECT id FROM orders) SELECT id FROM f
```

SQLite 与当前 raw query 都正确识别 F/f 为同一 CTE；实际物理依赖只有 orders。Skill 目录的 `_extract_table_names()` 固定 `case_sensitive=True`，把 f 推断为物理表，再将推断合并进 `metadata.tables`。即使 frontmatter 明确声明 `tables: [orders]`，合并后的依赖也变成 `[orders, f]`，随后成为可用性、授权和 readiness 的依据；所谓“advisory metadata”在这些调用点具有实际拒绝效果。

allowlist 只授权 orders 时，原 SQL 成功而 Skill 返回正常业务失败 table_access_denied；all 时 policy_allowed=true，但 schema_ready=false，默认发现列表隐藏该 Skill，执行返回缺表 ToolError。两协议一致；大小写一致的对照 Skill 正常发现、执行。不要以创建假表 f、放宽白名单或禁用 readiness 作为修复。

**13 日记录时该缺陷尚未修复；14 日已实施修复，见下方追加验收。** 建议保留显式依赖与自动推断的来源区别，按已解析的连接／方言推断真实物理依赖；授权与 readiness 使用同一分析结果。CTE 名比较与物理表身份比较应分别定义，不能简单给全体标识符 lower()。DRR-2026-081 补充这一未关闭边界；既有字符串／结构化拒绝验收结果继续有效。

### 后续设计建议与验证门槛

- MySQL CTE：对已核实的厂商／版本／lower_case_table_names 组合支持实际名称规则，未知组合保持精确拒绝；能力快照在可信适配器路径读取、按连接缓存。不要让启动时目录推断迫使数据库联网，也不要每次 agent 查询先做能力探测。矩阵还应保留非递归自／前向引用、物理同名表及嵌套遮蔽；CTE 识别放宽不豁免真实物理依赖。当前没有第二套服务，0/2 和 MariaDB 仍未独立完成。
- authorizer：设计目标是不增加正常 agent 工具步骤。主要运行代价是 Python 编译 callback、策略切换引发重新编译、共享连接下的并发协调／可能串行化，以及业务查询、可信 metadata、受管写入的上下文隔离。视图与底层表的授权语义必须明确；粗糙的底层表全拒会减少原本允许的操作。不能只改 callback 的可变策略状态，也不能用 IGNORE 静默改变结果。仍是分阶段候选方案，不是本轮上线承诺。
- 函数策略：建议只针对真实调用禁止 GET_LOCK／RELEASE_LOCK／RELEASE_ALL_LOCKS 和 SLEEP／BENCHMARK，并共同覆盖 raw query／Query Skill。字符串、列名／别名与普通分析函数不应误伤；VERSION 等既有信息函数决定不因此改变。真实需要锁管理／基准测量的业务会受限，需要明确的可信操作路径和清理；不把整个通用查询函数集改成白名单。MySQL 命名锁不会随事务提交／回滚释放，连接回池也不等于会话结束。生产策略尚未实施，没有测得其新增延迟。
- AST：SQLGlot 是候选，必须显式指定方言，结合 scope 分析建立本项目的 relations／CTEs／functions／statement-kind 结构化结果，共享给查询策略与 Skill 依赖。不能将所有 Table 节点直接当物理表，不能把 AST 成功等同真实服务器解析／授权成功；执行原 SQL，不自动转译／优化。先在代表查询集并行比较旧／新分析结果，验证 SQLite IN、PRAGMA 对象、CTE 顺序／递归／大小写、引号、参数及 MySQL 扩展，再决定生产替换；上线后应减少重复解析。新依赖、导入内存、解析时间、升级与规则维护是代价，不涉及假想历史调用方迁移。SQLGlot 的 MINOR 版本也可能破坏兼容，应锁定验证版本并做升级回归。
- 成本对照：把固定注入、服务器编排、模型完整任务分开。前两项本轮已有定点数据；端到端应控制工具发现清单、提示词、模型、Host、配置、缓存统计方式与任务真值，多次交错采样，并同时报告调用／回合、总／缓存输入、输出及通过率。计费需实际 tokenizer／价格／缓存类别，不能用字符估算替代。authorizer／AST 应另测冷／热编译、单请求及并发、启动时间／RSS；设置可接受门槛后再作取舍。

依据：[SQLite callback 的编译时机、视图 origin、缓存／重新编译说明](https://www.sqlite.org/c3ref/set_authorizer.html)、[MySQL 命名锁生命周期](https://dev.mysql.com/doc/refman/8.0/en/locking-functions.html)、[SQLGlot 方言与版本策略](https://sqlglot.com/sqlglot.html)、[SQLGlot Scope 源码](https://github.com/tobymao/sqlglot/blob/main/sqlglot/optimizer/scope.py)。以上是设计建议，除证据保留规范外，不视为维护者已经批准实现全部候选方案。

### 依赖与名称契约

- `SkillMetadata.tables` 保留 frontmatter 声明；目录不再把自动推断合并进去。缓存 SQL 的两个推断候选分别对应精确／ASCII 不区分大小写的 CTE 比较，按目标连接选用；不同连接不能互相污染结论。
- Query Skill full 投影的 `tables` 为目标连接所需的声明／推断依赖并集，新增 `declared_tables` 和 `inferred_tables` 显示来源，两个来源可以重叠。可用性、readiness、按表搜索与执行使用一致的依赖；显式额外依赖仍能限制 Skill。静态 SKILLS.md 只列声明，并说明运行时推断。变更直接同步当前调用方和测试，没有旧目录合并兼容层。
- CTE 比较与物理表授权分别处理；物理拼写、限定名、自引用／前向引用的依赖保留。MySQL 物理表白名单继续精确授权，CTE 识别不会自动折叠所有物理表名。
- SQLite 的标识符比较使用 ASCII 大小写映射，避免 Python Unicode lower() 把 K 与 K 视为同一授权对象。解码后的引号标识符保留真实首尾空格，`f` 与 `" f "` 不是同一对象；Skill 的物理表声明也保留字符，profile 等标签继续按其规则 trim/lower。元数据工具原有标识符语法限制没有扩大。

### MySQL 能力获取与成本

MySQL 适配器用固定的、没有 FROM 的常量语句验证名称是否重名：

```sql
WITH `mcp_Cte_Case_A` AS (SELECT 1 AS n),
     `mcp_cte_case_a` AS (SELECT 2 AS n)
SELECT 1 AS n
```

返回整数 1 表示这两个 ASCII 名可并存，采用精确比较；MySQL 1066／MariaDB 4004 的重名错误表示不区分 ASCII 大小写。其它异常不放宽，保持未知／精确比较，30 秒后可重试。成功结果按适配器实例缓存，close／服务重启清除；不依赖版本字符串猜测，也不读取主机／账号信息或物理表。依据为 [MySQL CTE 重名检测](https://github.com/mysql/mysql-server/blob/mysql-8.0.25/sql/parse_tree_nodes.cc#L1414)及[MariaDB 4004](https://mariadb.com/docs/server/reference/error-codes/mariadb-error-codes-4000-to-4099/e4004)。

构造、启动目录扫描、普通无歧义查询不做探测。真实 CTE 大小写歧义且最低必需物理依赖已授权时才探测；明确的读取拒绝、声明依赖拒绝、语句／系统对象／UNION 拒绝仍在探测之前。首次歧义请求因此可能有一次可信常量数据库 I/O，不能再笼统声称所有策略判断均无 I/O；业务 SQL 只在判定通过后执行。成功调用没有增加 agent 的 MCP 步骤。

当前 MySQL 8.0.25／lower_case_table_names=1 已确认不区分 ASCII CTE 大小写。[单次测量](review_2026_10_14/cte_probe_live.json)冷探测包含引擎创建、建连及首次导入约 146.40 ms，缓存 getter 约 0.006 ms；两者均为一个样本，不是完整查询延迟或普遍上限。两协议实测每实例恰好一次探测，重复请求使用缓存。非 ASCII 大小写变化仍保守；没有第二套服务，0/2 和 MariaDB 的独立真实矩阵仍未完成，模拟驱动结果不能替代它们。

### 锁／耗时函数策略建议

> 此处保留此前 CTE 批次的建议；后续已批准实施，见[新批次](V3_8_1_PHASE123_2026_10_14_ZH.md)。

建议下一步用小范围默认限制处理真实 GET_LOCK／RELEASE_LOCK／RELEASE_ALL_LOCKS 和 SLEEP／BENCHMARK 调用，共同覆盖 raw query 与 Query Skill。收益是减少会话锁副作用、连接／CPU／等待占用，以及执行后才超时的无效请求；明确前置错误方便恢复。MySQL 命名锁不会随事务提交或回滚释放，连接回池也不等于会话结束，[官方说明](https://dev.mysql.com/doc/refman/8.0/en/locking-functions.html)支持此处工程判断。

### JSON 规范是否减少信息

压缩与有来源引用的去重，对已经采集的原文可以无损；新清单给出压缩前后摘要，元数据只存一次，每协议明确引用其快照。此次应用结果记录比前一批仅抽取 text 的工具投影更完整，保留 content blocks、structuredContent、isError、meta、请求和调用时间。

| 层级 | 必须保留／适用限制 |
