## 问题、来源与修正

带双引号、带列列表的 CTE，例如 WITH "x"(n) AS (...)，被当前 sqlparse 分成名称和另一个含“列列表、AS、查询体”的 Identifier。原 _cte_header_token_ids 把后一个 Identifier 的全部叶子加入声明排除集，函数扫描因而跳过查询体。

在私有 SQLite 注册只返回 7 的 SLEEP／USER 等同名函数，独立确认 SQL 实际调用了函数；旧全表策略却允许。对应普通未加引号、反引号和方括号声明继续拒绝，说明是特定分组边界遗漏，而非全部 CTE 均失效。实际调用没有锁、等待、文件或账户读取副作用。

档案模块摘要核对后的重建确认：**锁／耗时路径原先就有该遗漏；上一批 DRR-2026-096 把文件／账户调用合并进共享扫描后，也把遗漏扩展到了这些类别。** 这是上一批合并未覆盖组合场景的回归，不能全部归为旧问题。五个来源对照同时保留前两阶段与修正后结果；它们是隔离源码重建，不冒充历史原生 Host 观察。

修正只按原始叶子 token 遍历声明，追踪括号深度，在声明层的 AS 处停止；只有 AS 之前的名字和列列表进入排除集。缺少可识别边界的形态不扩大排除。查询体中的真实调用继续走既有有限保留规则，不重写 SQL，不接入完整 AST，也不新增函数类别。

| 收益 | 代价与保留边界 |
| --- | --- |
| 关闭全表模式 raw 查询遗漏；危险 Skill 启动时隔离，缓存 Skill 运行时独立复验 | 当前关系身份解析仍有自己的保守子集；本次没有把带引号 CTE 列列表的 allowlist/readiness 支持一并扩展 |
| 共享函数扫描中的锁／耗时、文件、账户类别同步修正 | 同名自定义函数仍按既有保留规则拒绝，未建立任意函数副作用模型 |
| 普通声明、常量、字符串及函数引用身份保留 | 不新增依赖、配置、工具参数、Agent 必需调用步骤或元数据标识符语法；未重测模型 token／服务延迟，不能承诺零开销 |

已配置 analytics_demo_sqlite 是 allowlist，修改前原生两条探针先返回 relation_scope_unresolved，没有实际调用函数。全表模式问题与 readiness 关闭的 Skill 路径由私有 source-matched Client／安装包验证；不能把当前别名的保守拒绝当作全表路径已受保护。MySQL 引号语法及 ANSI_QUOTES 不由 SQLite 夹具推断；本批 MySQL 危险形态在 SQL 执行前即被拒绝。
