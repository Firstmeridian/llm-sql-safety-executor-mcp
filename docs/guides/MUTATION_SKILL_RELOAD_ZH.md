# Mutation Skill 受控热加载

[English](MUTATION_SKILL_RELOAD.md)

维护者将 Mutation 文件部署到已配置的 Skill 目录后，显式调用：

```json
{"skill_type": "mutation"}
```

工具为 `reload_skills`。省略参数或选择 `query` 仍只发布 Query，不导入或更换 Mutation。
Mutation 热加载要求 Skills 和 Mutation 执行均已启用，不能借此启用写入权限。
首次安装新工具参数及实现须先载入新服务进程，再刷新 Host 工具目录并由实际消费者核验；之后受支持的定义更新无需重启。

## 发布、预览与执行

候选通过定义、源文件及托管计划校验后，一次替换接收实例的活动目录。
新建、更新、禁用和移除均支持；无变化时不递增目录 `revision`，也不重新执行入口代码。
元数据和 Python 入口的实际字节共同决定变更，不能仅通过手写 `version` 判断。

严格catalog扫描区分真正删除与活动路径异常：变成普通文件、悬空／循环链接、无法核验的目录，或检测到扫描中消失／目录身份改变（即使同名项随后恢复）均拒绝整批，保留活动目录、revision及待确认预览。真正删除和解析到配置根目录内的有效目录符号链接仍支持。见[11月5日范围／目录补修](../validation/v3.8/V3_8_2_SCOPE_CATALOG_REPAIR_2026_11_05_ZH.md)。

| 发布时的状态 | 后续行为 |
| --- | --- |
| 定义未变，或更新的是另一 Skill | 原定义代际及已有预览保持，仍受期限、一次性消费和授权约束 |
| 定义改变、禁用或删除，令牌尚未消费 | 移除受影响的待确认预览；本次执行不得使用旧预览，是否重新预览由用户决定 |
| 旧版预览仍在生成，尚未签发令牌 | 签发时检查活动代际，已被替换则拒绝，不签发旧版可执行令牌 |
| 令牌先成功消费，随后发布新版 | 本次执行保持原版本的代码、计划和绑定值，允许完成 |
| 候选校验失败 | 活动目录和待确认预览保持；返回失败原因 |
| 定义从 A 更新到 B，再恢复 A | 恢复后分配新的代际，最初 A 的旧令牌不会恢复有效 |

发布与令牌签发／消费有确定顺序，短临界区不包括 Python 导入、数据库操作或等待用户。
预览签发后仍可能被稍后的发布或消费失效；收到预览不证明其未来必然有效。
MRTR 的保存审核、查看、重新询问、拒绝和确认也检查同一代际。
MRTR 仍要求其既有协议及 elicitation 能力，热加载不扩大 Host 支持范围。

已获准执行的操作不由热加载撤回。`committed`、`rolled_back` 和 `unknown` 按原写入契约解释；
响应丢失不等于未执行，不自动重试。每次 MCP 请求仍固定持有自己的目录快照。

确认请求在**可信Skill构造之前**被框架校验拒绝时（如删除、禁用、参数改名、连接范围缩小），保留具体原因并明确“本次请求未写入”；确认请求现在先匹配并消费令牌，再构造命令式Skill；构造器正常返回也不能绕过此顺序。缺失、无效、过期、不匹配或已消费令牌均不会运行本次Skill Python。获准后构造失败也不恢复令牌；命令式复验失败保留`validation_failed`，但整体结果为`unknown`，因为构造／验证可能已有副作用。预览Python运行后的代际拒绝不宣称本次未写入。见[10月31日补修](../validation/v3.8/V3_8_2_MUTATION_ADMISSION_HOST_BINDING_2026_10_31_ZH.md)。不能据此判断较早请求的结果，也不能把可能已产生副作用的构造器／执行回调错误一概称为未写入；不自动重试或生成新预览。见[定点补修](../validation/v3.8/V3_8_2_RESTART_IDENTITY_REFUSAL_REPAIR_2026_10_29_ZH.md)。

## Python 范围与失败边界

入口字节在独立候选模块中编译，不原地修改活动模块；托管与命令式 Mutation 都使用此发布机制。
入口外的共享 Python 依赖、框架、配置、密钥、连接和授权不热更，这些变更仍需重启。
已有 Query 对象保持，类型互转也需要重启。多个服务实例需分别发布，没有跨进程广播。
保留的Query名称在探测文件系统目标前跳过。

Skill 是维护者部署的可信 Python。加载会执行其顶层代码，原子性只保证目录引用发布，
不能回滚顶层代码的数据库、文件或其他外部副作用。顶层应限于导入与声明，业务操作应放在回调中。
候选失败后重试也可能再次执行顶层代码；工具因此标注 `destructive=true`、`idempotent=false`，
不表示加载本身获得了业务写入许可。无变化定义会直接复用，避免重复导入。

发布会扫描有界的待确认预览存储，成本随待确认条数增长；发布期间签发／消费按同一锁排序。
普通业务不扫描文件，已获准的数据库执行不占用发布锁。这里不承诺普遍提速或模型 token 减少。

## 调用 Agent 的成功确认

1. 核对 `success`、`skill_type`、`revision`、`added/changed/removed` 及 `invalidated_previews`。
   失效数只针对此次发布移除的待确认预览，不代表已取消任何在途执行。
2. 在实际消费实例、同一目标 `connection_id` 下核对受影响详情、参数和范围；新增／移除按需通过发现确认。
3. 业务任务需要写入时，使用新版定义重新预览并取得相应确认，再核验执行结果。
   单纯部署不要求执行写入，也不强制执行所有 Skill；已有相关任务检查可复用。
4. 响应丢失先检查实际加载的状态，不自动再次发布或执行；缺少某层证据时标为未验。

发布成功不证明数据库就绪、已授权或业务结果正确。普通业务调用不增加文件扫描或强制刷新步骤。
失败返回 `mutation_reload_failed`，并保留安全原因；并发发布返回 `reload_in_progress`。

Query 更新见 [Query 热加载](QUERY_SKILL_RELOAD_ZH.md)，需要新进程的变更见
[Codex 重启辅助](CODEX_MCP_RESTART_ZH.md)。实现取舍依据包括
[Python 模块重载说明](https://docs.python.org/3.12/library/importlib.html#importlib.reload)。

本批源码／安装／实库与原生／模型的验证状态分别见[验收报告](../validation/v3.8/V3_8_2_MUTATION_RELOAD_2026_10_29_ZH.md)。
