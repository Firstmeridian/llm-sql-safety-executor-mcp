# Query Skill 受控热加载

[English](QUERY_SKILL_RELOAD.md)

部署 Query Skill 文件后，显式调用 `reload_skills()` 发布经过校验的新目录快照，
无需为受支持的定义更新重启服务。普通业务调用继续使用已发布的定义。

## 适用范围与前置条件

- 启用 `skills.enabled=true`，将文件部署到已配置的 Skill 目录。工具默认
  `skill_type="query"`，不接受任意路径、SQL 或授权参数。
- 首次安装热加载实现，须先重启／重建服务进程，再更新 Host 工具目录并核验实际
  消费者。单纯配置刷新可能复用健康旧进程；已有热加载实现的服务无需为每次定义更新重启。
- 发布只影响接收调用的服务实例。同一目录可被多个 Host／子进程各自加载，彼此不广播
  或同步快照。主会话发布成功不能证明子会话已获得新定义；相关实例须分别发布并确认。

## 使用流程

1. 部署 `skill_def.md` 及其 `source` 引用的 `.sql` 文件。
2. 在需要使用新版定义的服务实例调用：

   ```text
   reload_skills()
   ```

   默认发布 Query；更新可信 Mutation 入口时另用显式 [Mutation 发布](MUTATION_SKILL_RELOAD_ZH.md)。
3. 按下节核对变更回执及受影响定义；任务需要执行时，再用新版参数进行已授权只读调用。
   发现／详情及执行须显式指定同一目标 `connection_id`，不能假定 canary 中指定的连接会被后续调用继承。

已有的详情读取或业务调用可直接用于确认，不要求普通查询增加固定管理步骤。

## 调用Agent的成功确认

调用方应在实际消费会话核验预期更新，再报告完成；不以请求受理或一句“已刷新”代替证据。

| 阶段 | 需要确认 | 可以报告的结论 |
| --- | --- | --- |
| 发布 | `success=true`，`revision` 及 `added/changed/removed` 与预期相符；无变更时版本不递增属正常 | 定义已发布到接收实例 |
| 消费可见 | 同一目标 `connection_id` 下读取受影响详情，核对参数／范围；新增可用发现确认，移除用精确搜索或详情缺失确认 | 该消费会话已看到预期更新 |
| 业务验证 | 任务需要执行时，以新版参数进行已授权只读调用并核对结果 | 本次业务验证通过 |

发布成功不代表数据库已就绪、已授权或业务结果已核验。仅部署／查看定义时，不强制执行
所有 Skill，也不访问未选择的连接；缺少某层证据时准确标为未验。无需另建通用确认工具，
服务端也不能保证任意模型都遵循此调用约定。失败或响应丢失按下节处理。

## 发布与失败契约

### 候选校验

- 复用定义、参数及启动 SQL 校验。无效定义、缺失／空 SQL、路径逃逸及检测到的加载期间
  文件变化拒绝整批候选，旧目录快照保持。
- 根目录缺失为错误；真实空目录可以删除全部 Query。删除完整子目录或 `enabled=false`
  表示移除；旧子目录仍在但定义缺失则拒绝。
- 活动 Query 路径变成普通文件、悬空／循环链接或无法核验的目录，或扫描中检测到其消失、
  目录身份改变，均拒绝整批候选，即使同名项随后恢复。失败保留目录、`revision` 及预览令牌。
  真正删除和解析到配置根目录内的有效目录符号链接仍支持。

### 原子发布与请求快照

校验后一次替换目录引用。每个 MCP 请求跨 await 固定持有同一快照；新请求使用新版。
在途引用保留旧快照，删除不立即撤销已进入的调用。普通调用不增加磁盘或数据库探测。

返回进程内 `revision`、`added/changed/removed`、保留及未激活的新 Mutation。
相同定义不递增版本并保留缓存；参数、范围、SQL 都纳入比较。原加载器不展示的
Markdown 正文不会因此成为运行时提示。

### 失败与响应丢失

| 情况 | 返回／处理 |
| --- | --- |
| 候选校验或发布失败 | 返回 `query_reload_failed` 及安全原因，保留旧目录；不能报告成功 |
| 并发更新 | 返回原因 `reload_in_progress` |
| 响应丢失 | 先检查已加载详情，不能推断发布失败，也不自动重试 |

## 范围与代价

原有 Mutation 元数据、Python 类、计划及预览令牌保持，即使磁盘定义修改或删除；
保留的 Mutation 名称在探测文件系统目标前跳过。Query 发布只报告新 Mutation，
不导入／激活。类型互转仍需重启。

Query 范围不重载 Mutation Python、共享依赖、连接、授权、配置或核心程序，不增加文件
监听、自动撤销或写入重试。连接、profile、readiness、SQL 策略和 authorizer 继续检查；
加载成功不等于获准执行。

显式更新在工作线程内校验；每次 MCP 请求增加轻量上下文绑定。部署时多一次管理调用及
一份工具定义，普通业务无需新增固定步骤，不承诺延迟或模型 token 普遍下降。

## Codex 重启辅助

核心代码、共享依赖或部署配置变化需要新进程时，见[重启与重连辅助](CODEX_MCP_RESTART_ZH.md)。
它区分配置刷新与真正替换进程，并要求从实际消费会话确认；只管理已有 Host，当前自动维护
只允许影响当前聊天，VS Code Codex 继续人工重连。Host 全局刷新须明确授权。
Query 文件发布则只影响接收实例并保留 Mutation 预览，与重启分开。
